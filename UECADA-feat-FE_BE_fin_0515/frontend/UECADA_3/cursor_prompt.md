# Cursor AI 프롬프트 — 스마트 팩토리 모니터링 대시보드

아래 프롬프트 전체를 복사해서 Cursor의 채팅창(`Cmd/Ctrl + L`)에 붙여넣고, 같이 첨부할 파일을 `@파일명` 으로 함께 첨부해 주세요.

---

## 📎 첨부할 파일 (Cursor 채팅에 같이 드래그)

1. `dropdown_flow.html` — 드롭다운 공정 흐름도 (현재 작업 중인 화면)
2. `1778746933698_image.png` — 공장 레이아웃 참고 이미지

---

## 프롬프트 본문 (이 아래부터 복사)

```
다음 명세에 따라 React + Tailwind CSS 기반 스마트 팩토리 모니터링 대시보드를 만들어줘.
첨부한 dropdown_flow.html 의 디자인 시스템(색상·폰트·카드 스타일·도형 아이콘)을 그대로 따르고,
첨부 이미지(공장 레이아웃)의 구조와 톤을 반영한 두 번째 화면을 추가해줘.

## 3. 화면 구성 (탭 전환)
────────────────────────────────────────
상단에 탭 2개:
  [공정 흐름 보기] | [공장 레이아웃 보기]

공통 상단바(둘 다 표시):
- 라인 카드 3개: Line-A (OEE 91%, 정상-파란톤), Line-B (OEE 84%, 경고-빨강톤), Line-C (OEE 88%, 기본)
- 상태 범례 칩 3개: 정상(녹), 주의(노), 경고(빨)
- 우측 끝: "레포트·인쇄" 다크네이비 버튼

────────────────────────────────────────
## 4. 화면 A — ProcessFlowView (드롭다운 흐름도)
────────────────────────────────────────
첨부한 dropdown_flow.html 을 React 컴포넌트로 그대로 포팅.
- 5개 공정 헤더 버튼이 가로 한 줄로 배치되고 화살표(→)로 연결
- 공정: 주조(원) → 가공(삼각형) → 세척(사각형) → 조립(육각형) → 검사(별)
- 각 버튼 클릭 시 아래에 드롭다운 패널이 펼쳐지면서 해당 공정 설비 카드들이 그리드로 표시
- 헤더 버튼에는: 도형 아이콘, 공정명, 상태 진행바(설비 수만큼 세그먼트), 설비 수 배지, 펼침 화살표
- 설비 카드 클릭 → 우측 EquipmentDetailPanel 갱신
- 여러 공정 동시 펼침 허용, 첫 로드 시 "주조" 자동 펼침
- 부드러운 max-height 트랜지션(0.35s ease)

────────────────────────────────────────
## 5. 화면 B — PlantLayoutView (공장 레이아웃, 첨부 이미지 기반)
────────────────────────────────────────
첨부 이미지 그대로의 구조로 만들 것. 핵심 사양:

[전체 컨테이너]
- 제목: "Plant Equipment Position / 공장 레이아웃 기반 설비 위치 표"
- 왼쪽 세로 사이드: [확대/축소/리셋] 줌 컨트롤 (+, -, ▢ 아이콘, 100% 표시)
- 우측: EquipmentDetailPanel (드롭다운 화면과 공유)

[메인 레이아웃 — 4행 구조]
각 행은 [좌측 라벨 영역 | 라인 블록 | 우측 라벨 영역] 의 3컬럼 그리드:

행 1: 자재 창고 | A-Block / Line A 주조 (CAST-01~04, 4대) | 검사실
행 2: 부품 창고 | B-Block / Line B 가공 (MACH-03, MACH-11, MACH-14, 3대) | 포장 구역
행 3: 사무실   | C-Block / Line C 조립 (WASH-03, ASM-05, ASM-09, ASM-12, 4대) | (행2와 동일)
행 4: 사무실   | D-Block / Line D 검사 (INSP-02, INSP-05, INSP-08, 3대) | 출하장

[설비 카드 스타일]
- 가로로 넓은 직사각형 카드 (이미지처럼 가로 길이를 차지)
- 카드 안: 상태 아이콘(✓/!/⚠) + 설비명(예: 주조기 1호) + 작은 ID(CAST-01)
- 상태별 테두리·배경:
  - 정상: 흰 배경 / 회색 테두리
  - 주의(yellow): 옅은 노랑 배경 / 노랑 테두리
  - 경고(red): 옅은 빨강 배경 / 빨강 테두리
- 카드 hover 시 살짝 떠오르고 그림자 진해짐
- 카드 클릭 → 우측 상세 패널 갱신 + 선택 상태 표시(파란 외곽선)

[라인 헤더 배지]
각 행 왼쪽 라인 블록 시작 부분에:
- "A-Block" 같은 작은 파란 칩
- 그 아래 "Line A 주조" 굵게

[라인 OEE 표시]
각 행 라인 블록 우측 끝에 작은 박스:
- 상태 칩 (정상/경고/이상)
- "OEE 91%" 같은 수치

[좌·우 라벨 영역]
- "자재 창고", "부품 창고", "사무실" 등은 회색 세로 텍스트 또는 작은 박스
- 점선 테두리로 영역 구분 (border-dashed)

[전체 배경]
- 옅은 그리드 도트/라인 배경 (드롭다운 화면과 동일)
- 전체를 큰 카드(rounded-xl, border) 안에 담기

────────────────────────────────────────
## 6. 우측 상세 패널 (EquipmentDetailPanel)
────────────────────────────────────────
두 화면이 공유하는 컴포넌트. 선택된 설비 정보 표시:
- 상단: "📈 설비 상세 정보" 라벨 + 상태 칩
- 큰 설비명 (예: "검사기 8호")
- 필드 카드들 (각각 outline 박스):
  - 위치 (예: "Line D 검사 · D-Block")
  - 설비 유형
  - 설비 ID
  - 목표 / 현재 (2열) — 검사기일 때만
  - 압력 / 금형 (2열) — 주조·가공·조립일 때
  - CT
- 하단 "최근 상태" 노란 박스 (현재 측정값 요약)

────────────────────────────────────────
## 7. Mock 데이터 (equipment.ts)
────────────────────────────────────────
타입 정의:
type Status = 'normal' | 'warn' | 'alert';
type Equipment = {
  id: string;
  name: string;
  type: string;
  stage: '주조' | '가공' | '세척' | '조립' | '검사';
  line: 'A' | 'B' | 'C' | 'D';
  block: string;
  status: Status;
  pressure?: string;
  temperature?: string;
  ct: string;
  target?: string;
  current?: string;
};

다음 데이터 포함:
- Line A 주조: CAST-01(정상), CAST-02(주의), CAST-03(정상), CAST-04(정상) — OEE 91%
- Line B 가공: MACH-03(정상), MACH-11(주의), MACH-14(정상) — OEE 84%, 경고 라인
- Line C 조립: WASH-03(정상), ASM-05(경고), ASM-09(정상), ASM-12(주의) — OEE 88%
- Line D 검사: INSP-02(주의), INSP-05(정상), INSP-08(정상, 기본 선택) — OEE 79% 이상
- 검사기 8호 기본값: 목표 32.00mm, 현재 31.98mm, CT 29.9s

────────────────────────────────────────
## 8. 인터랙션 요구사항
────────────────────────────────────────
- 라인 카드(Line A/B/C) 클릭 → 활성 라인 변경, 흐름도가 해당 라인 데이터로 갱신
- 설비 카드 클릭 → 두 화면 어디서든 우측 패널 갱신
- 탭 전환 시 선택된 설비와 활성 라인 상태 유지 (Context 또는 zustand)
- 모든 트랜지션은 200~350ms ease, 과하지 않게
- 키보드 접근성: 탭/엔터로 버튼·카드 활성화 가능
- 반응형은 1280px 이상 데스크톱 기준 (모바일 대응 불필요)
```

## 💡 Cursor 사용 팁

1. **첨부 우선**: `dropdown_flow.html` 과 레이아웃 이미지를 채팅창에 드래그해서 첨부한 뒤 프롬프트를 보내세요. 첨부 없이 보내면 디자인 일관성이 깨집니다.
2. **Composer 모드** (`Cmd/Ctrl + I`): 여러 파일을 한꺼번에 생성/수정할 때 사용하세요. 위 프롬프트는 Composer 에 최적화되어 있습니다.
3. **단계별 진행**: 한 번에 다 만들면 오류가 누적되니, 먼저 "1~3번까지만 먼저 만들어줘" 식으로 끊어서 요청하면 품질이 더 좋습니다.
4. **반복 수정**: 결과가 마음에 안 들면 `Cmd/Ctrl + K` 로 특정 코드만 선택해서 인라인 수정하는 게 빠릅니다.
